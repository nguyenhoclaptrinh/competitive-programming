Phần 1. Dinic Max Flow — Mạng luồng cực đại.
Đồ thị có hướng, nguồn s, hố t. Mỗi cạnh có capacity. Tìm luồng max từ s đến t.
Dinic: 2 pha lặp. BFS dựng Level Graph (level[u] = khoảng cách từ s chỉ dùng cạnh còn dư).
DFS tìm Blocking Flow trên Level Graph: chỉ đi cạnh level[v] = level[u]+1.
Con trỏ ptr[u] cực quan trọng: lưu cạnh đã duyệt, tránh duyệt lại → O(V^2 E).
Ví dụ: s=1, t=4. 1→2(10), 1→3(10), 2→3(2), 2→4(8), 3→4(9). Max flow = 17 (khớp min cut {1,2,3}|{4} = 8+9).

Phần 2. BFS Level Graph step-by-step.
Khởi tạo level[] = -1. level[s]=0. Queue=[s].
Pop u, duyệt cạnh u→v cap>flow. Nếu level[v]==-1: level[v]=level[u]+1, push v.
Kết thúc: level[t] != -1 có đường tăng.
Ví dụ: s=1. level[1]=0. 1→2 cap10→level[2]=1. 1→3 cap10→level[3]=1. Pop 2: 2→4 cap8→level[4]=2. Pop 3: 3→4 cap9→level[4] đã set. level[t]=2.

Phần 3. DFS Blocking Flow + ptr[u].
DFS(u, pushed): nếu pushed==0 hoặc u==t return pushed.
for (int &cid = ptr[u]; cid < adj[u].size(); ++cid):
  Edge &e = adj[u][cid]; int v = e.to;
  if (level[v]!=level[u]+1 || e.cap<=e.flow) continue;
  tr_pushed = DFS(v, min(pushed, e.cap-e.flow));
  if (tr_pushed>0): e.flow+=tr_pushed; adj[v][e.rev].flow-=tr_pushed; return tr_pushed;
return 0.
ptr[u] là THAM CHIẾU: sau khi cạnh bão hòa, lần sau BỎ QUA luôn. Không có ptr → TLE.

Phần 4. Ví dụ số Dinic chạy đầy đủ, khớp code từng dòng.
Mạng: s=1, t=4. Cạnh theo thứ tự thêm: 1→2(10), 1→3(10), 2→3(2), 2→4(8), 3→4(9).
Vòng 1: BFS cho level 1 bằng 0, 2 và 3 bằng 1, 4 bằng 2.
DFS lần 1: 1→2→4 đẩy 8 (kẹt ở 2→4). DFS lần 2: 1→2 còn dư 2 nhưng 2→3 bị chặn level, 2→4 hết dư → quay lui; 1→3→4 đẩy 9. Tổng 17.
Vòng 2: BFS chỉ tới được 2 (dư 2) và 3 (dư 1). Mọi cạnh vào 4 đều bão hòa. level 4 bằng -1 → dừng.
Max flow 17 = min cut {1,2,3} sang {4} = 8+9. Code Handbook tự xử lý cạnh ngược nên luôn đúng.

Phần 5. Code C++20 Dinic chuẩn.
struct Edge {int to; ll cap, flow; int rev;};
Dinic(n,s,t): adj(n+1), level(n+1), ptr(n+1).
addEdge(u,v,cap): adj[u].push({v,cap,0,(int)adj[v].size()}); adj[v].push({u,0,0,(int)adj[u].size()-1}).
bfs(): fill level -1. queue. level[s]=0. while q: u=pop, for e: if e.cap>e.flow && level[e.to]==-1: level[e.to]=level[u]+1; push.
dfs(u,pushed): if pushed==0||u==t return pushed; for(int&cid=ptr[u]; cid<adj[u].size(); ++cid)...
maxFlow(): flow=0; while(bfs()): fill ptr 0; while(p=dfs(s,INF)) flow+=p; return flow.
Mọi cap/flow dùng long long. INF = 1e18.

Phần 6. Min Cut & ứng dụng.
Sau maxFlow: BFS trên đồ thị thặng dư (cap>flow) từ s. Đỉnh đạt được = S. Còn lại = T. Min cut = các cạnh S→T ban đầu.
Min cut capacity = Max flow (Định lý Max-Flow Min-Cut).
Ứng dụng: bipartite matching (source→left cap1, right→sink cap1), project selection, image segmentation.
Dinic trên Unit Network (cap=1): O(E√V). Hopcroft-Karp là case đặc biệt.

Phần 7. Bẫy ICPC.
ptr[u] BẮT BUỘC dùng tham chiếu int&cid. Thiếu → TLE.
BFS level graph: CHỈ xét cạnh e.cap > e.flow. Cạnh ngược (rev) có cap=0 ban đầu, flow âm khi đẩy ngược → cap>flow đúng.
DFS đệ quy: depth ≤ V. V=3e5 đường thẳng → Stack Overflow! GIẢI PHÁP: viết DFS lặp (stack tay) HOẶC dùng BFS blocking flow (phức tạp hơn). Thực tế ICPC V≤1e4 thường đệ quy OK. Nếu V lớn → dùng ISAP hoặc HLPP.
Capacity 0: addEdge(u,v,0) hợp lệ. Multi-edge: addEdge gọi nhiều lần.
INF = 1e18, không dùng 1e9 (tràn khi cộng flow).

Phần 8. Tự kiểm tra 3 câu.
Câu 1: s→a(5), a→b(3), b→t(4), s→b(2), a→t(2). Max flow = ? Đáp: 6 (3 qua a→b→t, 2 qua a→t, 1 qua s→b→t; min cut {s,a,b}|{t} = 4+2).
Câu 2: Vì sao ptr[u] phải là tham chiếu? Đáp: lưu vị trí cạnh đã duyệt, lần sau bỏ qua cạnh bão hòa. Không có → TLE.
Câu 3: Min cut tìm như nào? Đáp: BFS đồ thị thặng dư từ s, cạnh S→T ban đầu là min cut.
Hẹn bài 8: Hopcroft-Karp Bipartite Matching.
