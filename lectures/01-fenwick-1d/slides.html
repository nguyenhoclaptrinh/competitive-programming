1/8 — Bài toán thực tế: vì sao mảng thường bị TLE?

Mục tiêu: hiểu vì sao cần Fenwick Tree. Nguồn: ICPC-Handbook §1.1

Cho mảng a[1..n] với n = 100.000 và q = 100.000 thao tác xen kẽ:

  • add(p, v): cộng thêm v vào ô a[p]. Ví dụ: add(5, 10) nghĩa là a[5] += 10.
  • sum(l, r): tính tổng a[l] + ... + a[r]. Ví dụ: sum(2, 7).

Ví dụ cụ thể Lấy n = 8, mảng ban đầu:

Nếu mỗi lần sum(l, r) bạn cho vòng lặp duyệt từ l đến r, mỗi truy vấn tốn O(n). Với 105 truy vấn × 105 phần tử = 1010 phép tính → chắc chắn quá thời gian (TLE).

Fenwick Tree chỉ dùng 1 mảng phụ tree[1..n] và 2 vòng lặp bit, đưa cả hai thao tác về O(log N) ≈ 17 bước với n = 105.

2/8 — So sánh 3 cách làm: duyệt tay, prefix-sum, Fenwick

Ý tưởng trực quan: thay vì lưu từng ô riêng lẻ hay lưu toàn bộ tiền tố, Fenwick lưu các khối có độ dài là lũy thừa của 2 (1, 2, 4, 8, ...). Truy vấn là ghép vài khối lại, cập nhật là sửa vài khối chứa điểm đó.

Hãy tưởng tượng bạn đổi tiền: thay vì toàn tờ 1 đồng (duyệt tay) hay 1 tờ mệnh giá lớn (prefix-sum), Fenwick có đủ tờ 1, 2, 4, 8,... nên ghép số tiền nào cũng chỉ cần vài tờ (log n tờ).

3/8 — Bí mật LSB: phép p & -p quyết định tất cả

Đây là trái tim của toàn bộ bài giảng — hiểu kỹ slide này là hiểu 70% Fenwick

Trong số nhị phân, p & -p tách ra bit 1 thấp nhất (Least Significant Bit). Độ dài đoạn mà nút p quản lý đúng bằng giá trị này:

Nút p quản lý đoạn (p − LSB, p] với LSB = p & −p

Cách nhớ nhanh: càng nhiều số 0 ở cuối nhị phân → khối càng dài. Nút là lũy thừa của 2 (2, 4, 8) luôn ôm một prefix dài.

4/8 — Truy vấn query(p): đi xuống bằng p −= p & −p

Bấm “Next bước” để xem hoạt hình với số thật: a = [3,1,4,1,5,9,2,6]

Công thức: muốn tổng a[1..p], lặp lại: cộng tree[p] rồi xóa bit 1 cuối cùng (p -= p & -p) cho tới khi p = 0.

Hành trình dự kiến: 7 → 6 → 4 → 0. Bấm “Next bước” để cộng từng khối — đáp án tổng sẽ hiện ra sau bước cuối cùng.
Bấm “Next bước” để chạy query(7): hành trình 7 → 6 → 4 → 0.

Tổng đoạn bất kỳ: sum(l, r) = query(r) − query(l−1). Ví dụ sum(2,7) = query(7) − query(1) = 25 − 3 = 22.

5/8 — Cập nhật add(p, v): đi lên bằng p += p & −p

Bấm “Next bước” để xem hoạt hình: add(5, 10) nghĩa là a[5] từ 5 lên 15

Công thức: khi a[p] tăng thêm v, mọi khối chứa p đều phải tăng theo. Lặp lại: tree[p] += v rồi cộng thêm bit 1 cuối cùng (p += p & -p).

Hành trình dự kiến: 5 → 6 → 8 → 16 (dừng). Bấm “Next bước” để cập nhật từng nút — giá trị tree mới sẽ hiện ra sau bước cuối cùng.
Bấm “Next bước” để chạy add(5,10): hành trình 5 → 6 → 8 → 16 (vượt n=8 nên dừng).

6/8 — Bẫy sống còn trong phòng thi ICPC: bắt buộc chỉ số 1-based

Lỗi này khiến nhiều đội mất 1 tiếng debug mà không hiểu vì sao treo máy
⛔ Không bao giờ gọi add(0, v) hay query(0) với vòng lặp cộng dồn.
Vì 0 & −0 = 0 nên lệnh p += p & −p trở thành p += 0 — p đứng yên tại 0 mãi mãi → vòng lặp vô tận → treo máy → TLE.
Nếu đề bài cho mảng 0-based (a[0..n−1]), hãy cộng 1 vào mọi chỉ số trước khi đưa vào Fenwick: add(idx+1, v).

Code sai (treo máy):

add(0, 5);
// p=0: 0 <= n đúng
// p += 0 & -0 → p += 0
// p vẫn = 0 → lặp vô tận!

Code đúng (0-based → 1-based):

// đề cho a[0..n-1]
for (int i = 0; i < n; i++)
    bit.add(i + 1, a[i]); // +1!
sum(l, r) = bit.query(r+1)
          - bit.query(l);
Bẫy 2 — tràn số 32-bit: tổng 105 số tới 109 vượt xa int → mọi mảng tree và biến sum phải dùng long long. Lưu ý thêm: query(0) luôn an toàn (vòng p > 0 thoát ngay, trả về 0) nên queryRange(1, r) chạy đúng — chỉ add(0, …) mới treo máy.

7/8 — Code chuẩn C++20: giải thích từng dòng

Học thuộc khung cấu trúc này, mang vào phòng thi viết lại chỉ trong 2 phút
C++20 · Fenwick Tree 1D 
struct Fenwick {
    int n;
    vector<long long> tree; // tree[1..n], tree[0] bỏ không dùng

    Fenwick(int n) : n(n), tree(n + 1, 0) {}

    // Cộng v vào ô p. Đi LÊN: p += p & -p
    void add(int p, long long v) {
        for (; p <= n; p += p & -p) // mỗi bước nhảy qua 1 khối cha
            tree[p] += v;
    }

    // Tổng a[1..p]. Đi XUỐNG: p -= p & -p
    long long query(int p) const {
        long long sum = 0;
        for (; p > 0; p -= p & -p) // mỗi bước gộp 1 khối
            sum += tree[p];
        return sum;
    }

    // Tổng a[l..r] = prefix(r) - prefix(l-1)
    long long queryRange(int l, int r) const {
        if (l > r) return 0;
        return query(r) - query(l - 1);
    }
};
3 điểm phải nhớ:
1. Mọi sum dùng long long (tránh tràn số 32-bit).
2. add đi lên (+), query đi xuống (−).
3. Độ phức tạp O(log N), bộ nhớ O(N).
Phân biệt nhanh:
• Cần range-add + range-sum? → Bài 1.2 (2 cây BIT).
• Cần min/max đoạn? → Sparse Table / Segment Tree.
• Chỉ cần cộng điểm + tổng đoạn? → Fenwick 1D là tối ưu nhất.
📌 Tóm tắt 30 giây: LSB = p & -p · add đi lên (+) · query đi xuống (−) · đoạn = query(r) − query(l−1) · 1-based · long long.

8/8 — Tự kiểm tra 3 phút + bài tập về nhà

Tự suy nghĩ trước khi bấm nút mở đáp án gợi ý
❓ Câu 1: Với n = 8, add(3, 7) sẽ cập nhật những nút nào trong mảng tree?
✅ Đáp án: 3 → 4 → 8. Giải thích: 3 (0011) có LSB=1 → 3+1=4. 4 (0100) có LSB=4 → 4+4=8. 8 (1000) có LSB=8 → 8+8=16 > n nên dừng.
❓ Câu 2: Khi gọi query(5), thuật toán ghé thăm những nút nào?
✅ Đáp án: 5 → 4. Giải thích: 5 (0101) có LSB=1 → 5−1=4. 4 (0100) có LSB=4 → 4−4=0 (dừng). Đoạn [1,5] được gộp từ [5,5] và [1,4].
❓ Câu 3: Vì sao query(0) chạy an toàn nhưng add(0, v) lại gây treo máy (TLE)?
✅ Đáp án: Do vòng lặp query có điều kiện dừng p > 0 (khi p=0 sẽ thoát ngay). Trong khi add kiểm tra p <= n và bước nhảy p += p & -p trở thành 0 += 0 → p mãi mãi là 0 dẫn đến vòng lặp vô tận!

Bài tập rèn luyện (làm ít nhất 2 bài trên LQDOJ / Codeforces):

  • Bài toán cơ bản: Dãy động và tổng đoạn (Fenwick thuần).
  • Đếm nghịch thế (Inversion Count): Duyệt từ phải sang trái kết hợp query(a[i]−1) và add(a[i], 1).
  • Tìm số 1 thứ k (Binary Lifting trên BIT): Đưa thao tác tìm kiếm về O(log N).
